Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Three tiers, two processes, one browser.

Shared state composables/

  • useFilters: module-level singleton refs for period, location, category and status. getCurrentFilters() maps them to API params (period becomes month, location becomes warehouse).
  • useI18n: English and Japanese; locale saved in localStorage; currency follows locale (USD or JPY).
  • useAuth: a hard-coded mock user with localized profile fields and tasks. No real authentication.

Data flow

What happens when a user changes a filter on the dashboard.

  1. Filter change. The user picks a value in FilterBar, which updates the shared refs in useFilters.
  2. View reacts. A watch in the view calls getCurrentFilters() and reloads its data.
  3. API call. api.js drops any filter set to all, builds a query string, and issues parallel axios GETs (for the dashboard: summary, orders, inventory, backlog).
  4. Server filtering. FastAPI runs apply_filters (warehouse, category, status; case-insensitive for the latter two) then filter_by_month over the in-memory lists, without mutating them.
  5. Validation. Responses pass through Pydantic response_models where one is declared, and return as JSON.
  6. Render. Views store raw results in refs and derive charts, totals and tables with computed properties.

Observations from the code

Things worth knowing before extending the project.

Missing endpoints. api.js calls /api/tasks (GET, POST, DELETE, PATCH), POST /api/purchase-orders and GET /api/purchase-orders/{id}, but none of these routes exist in main.py. The PurchaseOrder models are defined and purchase_orders.json is loaded, but only the backlog join uses them.
Unrouted view. views/Backlog.vue is not registered in the router; backlog data surfaces through the dashboard and BacklogDetailModal.
Hard-coded API URL. http://localhost:8001/api is fixed in api.js, and CORS allows every origin. Both are fine for a local demo and need changing for any deployment.
Duplicated quarter logic. /api/reports/quarterly repeats the month-to-quarter mapping instead of reusing QUARTER_MAP.
